# SEVER

SEVER — offline-first личный планер и PWA для задач, календаря, заметок, привычек, прогресса и фокус-сессий. Основной интерфейс публикуется через GitHub Pages, а синхронизация между устройствами работает через Supabase.

## Beta readiness · v76

Текущая версия подготовлена для первых нескольких тестеров.

- новый пользователь начинает с чистого планера без чужих целей, задач и заметок;
- первый запуск всегда открывается в теме **Calm Balance**;
- существующим пользователям сохраняется их выбранная тема и локальные данные;
- доступны три оформления с одинаковой структурой интерфейса: **Calm Balance**, **Cozy Mood**, **Focus Peak**;
- мобильная геометрия проверяется на 320, 360 и 390 px;
- нижняя навигация учитывает safe-area и не блокирует последние элементы экранов;
- таймер, Notes, Calendar, Progress, Habits и Settings проверяются в браузерных E2E;
- PWA/offline release использует актуальный cache lineage `sever-v72-mobile-consistency-v1`;
- перед merge v76 прошли browser, sync, concurrent sync, Undo/Draft, security, secret-scan и backend проверки.

Публичная версия проекта: `https://golovalisaia-hub.github.io/sever-planner/`

## Возможности

- задачи с датой, временем, длительностью, категорией и приоритетом;
- быстрый ввод фраз вроде `завтра английский 20 минут`;
- dashboard дня с задачами, фокусом, прогрессом и ближайшими действиями;
- мобильная навигация `Главная / Календарь / Создать / Заметки / Ещё`;
- связка `задача → таймер → завершение задачи → возврат на Главную`;
- круговой фокус-таймер с пресетами и своим временем;
- обычные заметки и чек-листы;
- папки и теги для организации заметок;
- закреплённые заметки;
- защищённые заметки с AES-GCM и PBKDF2-SHA-256;
- отдельные фильтры Notes: `Все / Заметки / Чек-листы / Защищённые`;
- привычки с отметками по дням;
- календарь и история задач;
- прогресс по дням и фокус-сессиям;
- Undo для удаления и изменения ключевых сущностей;
- локальное сохранение + IndexedDB backup;
- JSON backup/restore;
- облачная синхронизация между устройствами;
- offline-режим и установка как PWA;
- встроенный SEVER AI с серверной изоляцией provider key.

## Первые тестеры

Для beta-проверки достаточно 2–5 человек. Лучше, чтобы хотя бы один тестировал на iPhone/Safari, один на Android/Chromium и один на ПК.

Попросите каждого тестера пройти один и тот же короткий сценарий:

1. Открыть SEVER в новом браузере или приватном профиле и проверить, что первой активна **Calm Balance**.
2. Создать аккаунт или войти, если нужна синхронизация между устройствами.
3. Создать задачу на сегодня и задачу без времени.
4. Открыть задачу, запустить таймер и проверить завершение связанной задачи.
5. Создать обычную заметку, чек-лист, папку/тег и закрепить заметку.
6. Удалить заметку и проверить `Отменить`.
7. Создать защищённую заметку и убедиться, что после блокировки содержимое снова требует пароль.
8. Проверить Calendar, Progress и Habits.
9. Переключить Calm / Cozy / Focus и убедиться, что структура экрана не прыгает.
10. Если используется аккаунт — открыть тот же аккаунт на втором устройстве и проверить синхронизацию.

Если найден баг, полезно записать: устройство, браузер, экран SEVER, действие перед ошибкой и скриншот. Не присылайте пароли, токены или содержимое защищённых заметок.

## Публикация

GitHub Pages должен публиковаться из ветки `main`, папки `/(root)`.

SEVER умеет работать полностью локально без аккаунта. Для синхронизации нужны только публичный Supabase Project URL и publishable/anon key. `service_role` key никогда не должен попадать в GitHub, HTML или браузерный JavaScript.

## SEVER Cloud Sync

Cloud Sync сохраняет UX offline-first: действие сначала фиксируется локально, затем компактная очередь изменений синхронизируется с Supabase. При отключённой сети пользователь может продолжать работу, а накопленные изменения отправятся после восстановления соединения.

### Настройка Supabase

1. Создайте проект Supabase и дождитесь статуса **Active**.
2. В `Authentication → Providers → Email` включите Email.
3. Примените миграции из `supabase/migrations/` по порядку.
4. В `Project Settings → API` возьмите `Project URL` и публичный `Publishable key` (или legacy `anon` key).
5. Добавьте GitHub Pages origin/redirect URL проекта в настройки Authentication URL Configuration.
6. Заполните `supabase-config.js` по примеру `supabase-config.example.js`.

Публичный ключ допустим в статическом приложении: доступ к пользовательским данным ограничивают Row Level Security policies. Серверные секреты и provider keys должны оставаться только на серверной стороне.

### PC ↔ phone

1. Войдите в один и тот же аккаунт на первом устройстве.
2. Если на устройстве уже были локальные данные, подтвердите перенос в облачный аккаунт только один раз.
3. Создайте задачу, заметку, привычку и завершённую фокус-сессию.
4. Войдите тем же аккаунтом на втором устройстве.
5. Проверьте появление данных и обратную синхронизацию после новой правки со второго устройства.

Защищённая заметка остаётся зашифрованной; пароль защищённой заметки не синхронизируется.

## Безопасность и модель данных

- пользовательские таблицы используют RLS и owner-scoped проверки через `auth.uid()`;
- локальный cache и cloud queue разделены по аккаунтам;
- поздний ответ старой сессии не должен заменять состояние нового аккаунта;
- удаления синхронизируются через tombstones/soft-delete модель;
- конфликтующие изменения используют версионирование полей и детерминированный merge;
- таймер хранит тики локально, а в облако отправляется завершённая фокус-сессия;
- защищённые заметки хранят ciphertext/IV/salt/KDF-параметры, а не пароль и не plaintext;
- draft защищённой заметки не должен попадать в persistent storage;
- pin/tags защищённых заметок ограничены так, чтобы не утекала смысловая метаинформация.

Если пароль защищённой заметки забыт, восстановить её содержимое нельзя. Перед важными изменениями используйте резервную копию.

## Проверка

Полный CI запускает unit/regression, Chromium E2E, concurrent sync, static QA, sync core, Draft/Undo regressions, security suite, secret scan и backend tests.

Основные локальные проверки:

```bash
node --test tests/*.test.mjs
node tests/qa_static.mjs
node tests/sync_core.mjs
node tests/cloud-draft-regression.test.mjs
node tests/entity-undo-regression.test.mjs
node --test tests/security/*.test.*
```

Browser E2E используют Playwright и проверяют desktop + телефоны 320/360/390 px, три темы, основные экраны, Notes, PWA/offline, таймер и mobile hit areas.

Auth/RLS integration-тесты, которым нужны одноразовые внешние тестовые аккаунты, могут отображаться как `SKIP`, если соответствующие CI secrets не настроены. Это не должно маскироваться как `PASS`.

## Python API foundation

Экспериментальный Python API находится в `backend/`. GitHub Pages публикует только статический PWA; backend требует отдельного размещения.

```bash
py -m venv .venv
.\.venv\Scripts\python -m pip install -r backend\requirements.txt
cd backend
..\.venv\Scripts\python -m pytest
..\.venv\Scripts\uvicorn app.main:app --reload
```
