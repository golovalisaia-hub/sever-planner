# SEVER

SEVER — личный планер, который постепенно развивается в умный календарь. Текущий интерфейс — быстрый офлайн-first PWA для GitHub Pages; рядом добавлен безопасный Python foundation для будущей синхронизации, календаря и AI-инструментов.

## Возможности

- чистый первый запуск без чужих целей и задач;
- собственные цели с любым сроком и временем занятий;
- любые личные задачи и привычки;
- быстрый ввод фраз вроде `завтра английский 20 минут`;
- связка задачи с фокус-таймером: обучение, работа или обычное выполнение;
- обычные заметки без лишних отметок;
- чек-листы с отдельными галочками, действием «Отметить всё» и автоматическим прогрессом;
- папки для заметок и быстрые фильтры по темам;
- пароль для отдельных заметок: содержимое шифруется AES-GCM, ключ получается из пароля через PBKDF2-SHA-256;
- отдельный круговой таймер со своим временем;
- подсказка следующего шага и прогресс дня;
- автоматический перенос просроченных личных задач;
- карта прогресса и недельный итог;
- светлая и тёмная темы;
- резервная копия и восстановление JSON;
- офлайн-режим и установка как PWA.

## Публикация

Загрузите содержимое этой папки в корень репозитория GitHub. Затем откройте `Settings → Pages`, выберите `Deploy from a branch`, ветку `main` и папку `/(root)`.

По умолчанию SEVER работает локально и не требует аккаунта. Для синхронизации между устройствами добавьте только публичный Supabase URL и publishable/anon key. Никогда не добавляйте service_role key в GitHub или браузер.

Пароли защищённых заметок нигде не сохраняются. Если забыть пароль, восстановить такую заметку нельзя. Перед важными изменениями скачивайте резервную копию в настройках.


## SEVER Cloud Sync

Cloud Sync — необязательное продолжение offline-first режима: интерфейс сразу сохраняет действия локально, а затем отправляет компактную очередь изменений в Supabase. Без настройки Supabase планер полностью работает как прежде — только в браузере.

### Настройка Supabase

1. Создайте проект в [Supabase](https://supabase.com/dashboard) и дождитесь статуса **Active**.
2. В **Authentication → Providers → Email** включите Email. Для первого теста можно отключить `Confirm email`; в production лучше оставить подтверждение почты включённым.
3. Откройте **SQL Editor → New query**, вставьте содержимое [`supabase/migrations/001_initial_cloud_sync.sql`](supabase/migrations/001_initial_cloud_sync.sql) и нажмите **Run**. Скрипт создаёт таблицы, RLS-политики, encrypted-notes constraint и realtime-публикацию.
4. В **Project Settings → API** скопируйте `Project URL` и публичный `Publishable key` (или legacy `anon` key). Вставьте их в локальный [`supabase-config.js`](supabase-config.js), ориентируясь на [`supabase-config.example.js`](supabase-config.example.js).
5. Добавьте `https://golovalisaia-hub.github.io` в **Authentication → URL Configuration → Redirect URLs**. Для локальной проверки добавьте также URL локального сервера, например `http://localhost:4173`.
6. Задеплойте изменённый `supabase-config.js` вместе с приложением на GitHub Pages.

Публичный ключ допустим в статическом приложении: доступ защищают включённые Row Level Security policies. `service_role` key сюда никогда не подходит.

### Как проверить PC ↔ phone

1. Откройте SEVER на ПК, нажмите аккаунт в левом нижнем углу (или в настройках на телефоне), создайте аккаунт по email и паролю.
2. Если на устройстве уже есть задачи, заметки или привычки, подтвердите «Перенести в облако». Этот выбор сохраняется для аккаунта, поэтому записи не дублируются после следующего запуска.
3. Создайте `Python`, завершите её, добавьте обычную заметку, checklist и защищённую заметку.
4. Откройте ту же ссылку на телефоне, войдите тем же email. Данные должны появиться после синхронизации; секретная заметка останется зашифрованной и будет запрашивать её собственный пароль.
5. Создайте на телефоне «Тренировка», затем снова откройте ПК. Изменение придёт через realtime или обычную фоновую синхронизацию.

При отключённой сети можно продолжать работать. Изменения остаются на устройстве и отправляются после восстановления соединения. JSON backup/restore сохранён; восстановленные данные тоже попадут в очередь синхронизации.

### Безопасность и модель данных

- Каждая таблица имеет RLS с проверкой `auth.uid()` — аккаунт не может читать или изменять данные другого аккаунта.
- Кэш и очередь изолированы по `user_id`; после выхода предыдущий облачный набор не показывается следующему пользователю.
- Удаление — soft delete с `deleted_at`; последний `updated_at` выигрывает, а сервер отклоняет устаревшие повторные записи.
- Таймер остаётся локальным. В облако попадает только завершённая фокус-сессия, не каждый тик.
- Защищённые заметки сохраняют на сервере только AES-GCM ciphertext, IV, salt и параметры KDF. Пароль и открытый текст не отправляются.

## Python API foundation

API находится в [`backend/`](backend/). В development он запускается с SQLite, а production-конфигурация предназначена для PostgreSQL. GitHub Pages продолжает публиковать только PWA: Python API нужно размещать отдельно.

```bash
py -m venv .venv
.\.venv\Scripts\python -m pip install -r backend\requirements.txt
cd backend
..\.venv\Scripts\python -m pytest
..\.venv\Scripts\uvicorn app.main:app --reload
```

Контракты API требуют временную идентичность через `X-SEVER-User-Id`; это сознательная граница доступа для разработки, которая будет заменена безопасной аутентификацией до production. Подробнее: [ARCHITECTURE.md](ARCHITECTURE.md).
