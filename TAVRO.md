# TAVRO

**Твои мысли. В твоём ритме.**

Telegram-first AI планер. Одна фраза — голосом или текстом — превращается во
встречи, задачи, заметки и записи дневника. Человек проверяет результат и
сохраняет одной кнопкой.

TAVRO построен **рядом** с SEVER, а не поверх него. Ни один файл SEVER не
изменён, миграции только добавляют таблицы, данные существующих пользователей
не трогаются.

## 1. Аудит SEVER: что было найдено

Проверено фактическое состояние репозитория, а не описание.

### Что работает и переиспользуется

| Что | Состояние | Как используется в TAVRO |
|---|---|---|
| Статический PWA-планер (`index.html`, `app.js`, ~40 модулей `sever2-*`) | Работает, опубликован на GitHub Pages | Не трогается. TAVRO — отдельное приложение в `tavro/` |
| Supabase Auth + RLS + облачная синхронизация (`js/cloud-runtime.js`, миграции 001–006) | Работает, покрыто тестами | Модель владения записями взята за образец; таблицы отдельные |
| Edge Function `sever-ai` (Deno, 520 строк) | Работает: провайдер за сервером, строгая валидация, подписанные подтверждения, квоты через `sever_claim_ai_quota` | Архитектура повторена и расширена. Код не переиспользован напрямую, чтобы не связать релизы двух продуктов |
| Push-напоминания (миграции 007–017, pg_cron + pg_net + Vault) | Работает | Схема планировщика повторена для `tavro_reminders` |
| Тестовая инфраструктура: `node --test` по `.ts` напрямую, Playwright на 320/360/390/desktop | Работает | Используется как есть |

### Что пришлось исправить или сделать иначе

1. **`backend/app/security.py` — авторизация по заголовку `X-SEVER-User-Id`.**
   Клиент просто объявляет, кто он. В комментарии это помечено как временное
   решение, но для публичного Telegram-продукта оно недопустимо. TAVRO **не
   использует** этот бэкенд: личность приходит только из подписи Telegram,
   проверенной на сервере. FastAPI-часть осталась нетронутой — это заготовка
   SEVER, а не рабочий контур.
2. **У SEVER нет Telegram-контура вообще** — ни бота, ни Mini App, ни платежей,
   ни распознавания речи. Всё это написано с нуля.
3. **`sever-ai` разбирает одну команду за раз.** Ключевая идея TAVRO — одна
   фраза даёт несколько разных объектов — потребовала другой схемы ответа
   модели и отдельного этапа предпросмотра.
4. **Статический тестовый сервер отдавал `index.html` только для `/`.**
   Исправлено: теперь любой путь-каталог отдаёт свой `index.html`.

### Общая бизнес-логика

Вынесена в `supabase/functions/_shared/`:

- `validation.ts` — примитивы проверки на границе доверия;
- `datetime.ts` — работа с часовыми поясами, разрешение относительных дат,
  перевод локального времени в UTC через DST.

Эти модули не зависят ни от TAVRO, ни от SEVER и рассчитаны на использование
обоими продуктами. SEVER пока продолжает пользоваться своими копиями — перевод
его на общие модули это отдельное изменение, которое затрагивает работающий
продукт и в этой работе не делалось.

## 2. Архитектура

```
Telegram
  ├── Bot  ──webhook──►  tavro-bot    (Deno Edge Function)
  └── Mini App ──initData──►  tavro-api  (Deno Edge Function)
                                  │
              pg_cron ──►  tavro-reminders
                                  │
                        service_role ▼
                          PostgreSQL (Supabase)
                          tavro_* таблицы, RLS, без доступа для anon
```

### Где проходит граница доверия

| Вход | Чем подтверждается личность |
|---|---|
| Webhook бота | Секрет `X-Telegram-Bot-Api-Secret-Token`, зарегистрированный в `setWebhook` |
| Запрос Mini App | Подпись `initData` по алгоритму Telegram: `HMAC_SHA256(key="WebAppData", bot_token)` → `HMAC_SHA256(key=secret, data_check_string)`. Сравнение за постоянное время, проверка свежести `auth_date` |
| Быстрый ввод с телефона | Отдельный токен с областью действия «только создать запись», хранится как SHA-256, отзывается, ограничен по частоте |
| Cron напоминаний | `Authorization: Bearer <TAVRO_CRON_SECRET>` |

**ID пользователя, присланный клиентом, не используется никогда.** Поля
`user_id`, `account_id`, `telegram_id`, `role`, `entitlement`, `dailyAiActions`
отвергаются на входе любым запросом и любым ответом модели.

## 3. Правило, ради которого всё это сделано

**Модель не придумывает дату и время.**

Модель возвращает не момент времени, а одно из трёх:

```json
"date": null                          // пользователь не назвал день
"date": { "relative": "tomorrow" }    // сказал «завтра»
"date": { "absolute": "2026-09-20" }  // назвал число
```

Относительные значения берутся из закрытого словаря (`today`, `tomorrow`,
`next_monday`, `in_<N>_days`, …) и разрешаются на сервере против **сегодняшнего
дня пользователя в его часовом поясе**. `null` остаётся `null` — задача просто
сохраняется без даты.

Любое другое значение в поле даты — ошибка, запись не сохраняется. Это
проверяется тестами: строка «завтра» в поле абсолютной даты, неизвестный токен,
дата дальше пяти лет — всё отвергается.

Так же устроено время: «утром», «вечером», «попозже» временем не считаются.

### Эталонный разбор

Фраза:

> завтра встреча с Андреем в 15:00, потом изучить Python, оплатить интернет и
> запиши в дневник, что сегодня закончил проект

Результат (тест `одна фраза разбирается в четыре разные записи`):

| Тип | Название | Дата | Время |
|---|---|---|---|
| Встреча | Встреча с Андреем | завтра | 15:00 |
| Задача | Изучить Python | — | — |
| Задача | Оплатить интернет | — | — |
| Дневник | Закончил проект | сегодня | — |

«Потом» датой не стало. Это одно AI-действие по тарифу, сколько бы записей оно
ни создало.

## 4. Выбор ИИ-провайдера

### Что удалось проверить и что нет

**Важное ограничение этой работы:** сетевой шлюз среды разработки блокирует
`yandex.cloud`, `aistudio.yandex.ru`, `cloud.yandex.com`, `core.telegram.org` и
`docs.aiogram.dev`. Официальную документацию и прайс-листы открыть не удалось.

Поэтому:

- **никакие цены в этом документе не приводятся как факт** — ни рубли за
  распознавание, ни стоимость токенов, ни курс Telegram Stars;
- параметры API (эндпоинты, формы запросов) взяты по известным публичным
  описаниям и **помечены ниже как требующие проверки** перед запуском;
- код написан так, что смена провайдера и любых числовых параметров — это
  изменение переменных окружения, а не переписывание приложения.

### Сравнение кандидатов

| Критерий | Yandex AI Studio + SpeechKit | OpenAI-совместимый (Groq / Mistral / OpenRouter) | Whisper-совместимый STT |
|---|---|---|---|
| Русская речь | Профильная сильная сторона, модели обучены на русском | — | Whisper large-v3 хорошо знает русский |
| Разговорные фразы | YandexGPT ориентирован на русский разговорный | Зависит от модели | — |
| Структурированный JSON | `jsonObject: true` | `response_format: {type:"json_object"}` | — |
| Несколько действий в фразе | Обеспечивается промптом и схемой, не провайдером | То же | — |
| Оплата из России | Обычный счёт Yandex Cloud в рублях | Как правило требует зарубежной карты | Зависит от площадки |
| Коммерческое использование | Разрешено по условиям Yandex Cloud | Зависит от площадки | Зависит от площадки |
| Формат аудио Telegram (OggOpus) | Принимается напрямую | — | Принимается напрямую |

**Рекомендация: Yandex AI Studio + SpeechKit как основной провайдер,**
OpenAI-совместимый адаптер как запасной. Решающие аргументы — русский язык,
возможность платить из России и то, что STT и LLM берутся у одного поставщика
по одному ключу. Это рекомендация по доступности и совместимости, а не по
цене: цену нужно проверить по официальному прайсу (см. чек-лист ниже).

### Интерфейсы

```ts
interface AIProvider {
  complete(input: { system, user, signal?, maxTokens? }):
    Promise<{ json, usage: { inputTokens, outputTokens }, raw }>;
}

interface SpeechProvider {
  transcribe(input: { audio, mimeType, durationSeconds, language?, signal? }):
    Promise<{ text, seconds, provider }>;
}
```

Реализовано: `YandexGptProvider`, `OpenAICompatibleProvider`,
`YandexSpeechKitProvider`, `WhisperCompatibleProvider`. Переключение —
`TAVRO_AI_PROVIDER` и `TAVRO_SPEECH_PROVIDER`.

### Что обязательно проверить перед запуском

1. Актуальные цены SpeechKit STT (единица тарификации и стоимость) и
   Foundation Models (цена за 1000 токенов) по официальному прайсу.
2. Форму ответа `foundationModels/v1/completion` и имена полей `usage`
   (`inputTextTokens`, `completionTokens`) — адаптер их читает.
3. Что параметр `jsonObject` поддерживается выбранной моделью.
4. Что `stt:recognize` принимает OggOpus нужной длины (адаптер ограничивает
   120 секундами и 2 МБ; для более длинного нужен асинхронный API).
5. Курс Telegram Stars и фактическую выплату разработчику — см. раздел 6.

Пока ключи не заданы, бот честно отвечает «ИИ ещё не подключён на сервере»,
а планер продолжает работать.

## 5. Безопасность

| Требование | Как выполнено | Тест |
|---|---|---|
| Проверка initData по официальному алгоритму | `telegram.ts:verifyInitData`, сравнение хеша за постоянное время, проверка свежести и «будущей» метки времени | `tavro-core`, `tavro-api` |
| Не доверять клиентскому ID | Личность только из подписи; `user_id`/`account_id`/`role`/`entitlement` отвергаются | `tavro-api`, `tavro-security` |
| Изоляция данных | Каждый запрос в `store.ts` фильтрует по `account_id`; чужой черновик, задача и встреча не открываются | `tavro-bot`, `tavro-api` |
| Supabase RLS | RLS + `force row level security` на всех `tavro_*`, `revoke all from anon, authenticated`, доступ только `service_role` | `tavro-security` |
| Хранение ключей | Только в окружении Edge Functions и Vault; в клиенте нет ни одного имени секрета | `tavro-security` |
| Rate limiting | `tavro_rate_check` — фиксированное окно на аккаунт и корзину | `api.ts` |
| Проверка платежей | Доступ только по `successful_payment`; идемпотентность по `telegram_payment_charge_id` | `tavro-bot` |
| Защита от повторных webhook | `tavro_claim_update` по `update_id` | `tavro-bot` |
| Prompt injection | Фраза передаётся как значение JSON, не склеивается с инструкциями; ответ модели проверяется строгой схемой; SQL модель не видит | `tavro-security` |
| Безопасные миграции | Только `create table if not exists`; ни одной SEVER-таблицы не изменено, ничего не удаляется | `tavro-security` |
| Личное не в логах | Ни одного `console.*` во всём коде TAVRO; ошибки БД не показывают драйверных подробностей | `tavro-security` |

## 6. Тарифы

Рублёвые цены заданы владельцем и в коде не вычисляются:

| Тариф | Цена | Продление | AI-действий в сутки |
|---|---|---|---|
| FREE | 0 ₽ | — | 3 |
| PRO — месяц | 250 ₽ | Автопродление каждые 30 дней (Telegram Star subscription) | 100 |
| PRO — год | 1 800 ₽ | Разовая покупка на 365 дней, **без автопродления** | 100 |
| PRO — навсегда | 5 000 ₽ | Разовая покупка, доступ без срока | 50 |

Годовой и пожизненный тарифы нигде не называются автопродлеваемыми — это
проверяется тестом.

### Цены в Stars

Цена в Stars **настраивается на сервере** и в коде не зашита:
`TAVRO_STARS_PRO_MONTH`, `TAVRO_STARS_PRO_YEAR`, `TAVRO_STARS_PRO_LIFETIME`.

Пока переменная не задана, тариф **нельзя купить**: кнопка не показывается, в
списке написано «Цена в Stars пока не настроена», а прямой запрос счёта
возвращает 503. Это сделано намеренно — лучше не продать, чем продать по
выдуманному курсу.

Чтобы назначить цены, нужно взять текущий курс Stars и фактическую выплату
разработчику из официальных источников Telegram/Fragment и посчитать:

```
цена_в_stars = целевая_цена_в_рублях / выплата_разработчику_за_1_star
```

Проверить прибыльность по формуле из следующего раздела и записать значения в
секреты функций.

### Честные условия использования ИИ

Пожизненный доступ за 5 000 ₽ не означает безграничных расходов на внешние API.
Условие показывается **до оплаты**, в описании счёта и в приложении:

> Пожизненный доступ — это доступ к TAVRO без срока и без повторной оплаты.
> AI-часть работает на платных внешних сервисах, поэтому у неё есть дневная
> норма: 50 действий в сутки. Норму для уже купленного тарифа мы не снижаем.
> Планер, напоминания и все записи остаются доступны без ограничения.

Версия условий записывается в `tavro_subscriptions.terms_version` в момент
покупки и при последующих изменениях не переписывается.

Себестоимость одного AI-действия считается так:

```
голосовое = STT(длительность) + LLM(вход + выход)
текст     = LLM(вход + выход)
```

Подставьте актуальные тарифы провайдера, умножьте на дневную норму и на срок
окупаемости — и сверьте с ценой тарифа. Фактическое потребление видно в
`tavro_ai_usage`: там есть токены, секунды аудио и задержка по каждому запросу.

Я не могу выполнить эти шаги: они требуют ваших аккаунтов и секретов.

   | Переменная | Назначение |
   |---|---|
   | `TAVRO_BOT_TOKEN` | Токен бота |
   | `TAVRO_WEBHOOK_SECRET` | Случайная строка ≥ 16 символов, та же в `setWebhook` |
   | `TAVRO_CRON_SECRET` | Случайная строка для планировщика |
   | `TAVRO_MINIAPP_URL` | HTTPS-адрес Mini App |
   | `TAVRO_APP_ORIGINS` | Origin Mini App для CORS |
   | `TAVRO_AI_PROVIDER` | `yandex` \| `groq` \| `mistral` \| `openrouter` \| `openai-compatible` |
   | `TAVRO_YANDEX_API_KEY`, `TAVRO_YANDEX_FOLDER_ID` | Для Yandex |
   | `TAVRO_AI_API_KEY`, `TAVRO_AI_MODEL`, `TAVRO_AI_BASE_URL` | Для OpenAI-совместимого |
   | `TAVRO_SPEECH_PROVIDER` | `yandex` \| иной |
   | `TAVRO_SPEECH_API_KEY`, `TAVRO_SPEECH_BASE_URL`, `TAVRO_SPEECH_MODEL` | Для Whisper-совместимого |
   | `TAVRO_STARS_PRO_MONTH` / `_YEAR` / `_LIFETIME` | Цены в Stars |

4. **Vault** (для cron): секреты `tavro_project_url` и `tavro_cron_secret`.
5. **Развернуть функции:** `tavro-bot`, `tavro-api`, `tavro-reminders`.
6. **Webhook:**
   `setWebhook` на `https://<project>.supabase.co/functions/v1/tavro-bot`
   с `secret_token = TAVRO_WEBHOOK_SECRET` и списком `allowed_updates`,
   включающим `message`, `callback_query`, `pre_checkout_query`.
7. **Menu Button:** `setChatMenuButton` на Mini App.
8. **Mini App:** опубликовать `tavro/` по HTTPS и указать адрес в BotFather.
9. **Цены в Stars:** посчитать и задать (раздел 6).

Платежи не включатся сами: пока `TAVRO_STARS_*` не заданы, покупка недоступна.
В `main` ничего не сливалось, публичные платежи не запускались.

## 8. Быстрый запуск с телефона

Одинаковой поддержки на всех устройствах нет, и в интерфейсе это сказано прямо.

**Самый надёжный способ на любом телефоне** — закрепить чат бота сверху и
записывать голосовое прямо в нём.

**iPhone:** кнопка «Действие» (iPhone 15 Pro и новее), касание задней панели,
Быстрые команды. **Android:** ярлык чата на домашний экран, «Добавить на
главный экран» для Mini App.

Если используется отдельная команда, она обращается к
`POST /functions/v1/tavro-api/quick/capture` с токеном быстрого ввода в
заголовке `Authorization: Bearer tvq_…`. Этот токен:

- умеет только создавать записи — чтение, настройки и покупки ему закрыты;
- хранится как SHA-256, в открытом виде показывается один раз;
- отзывается в настройках, ограничен по частоте, не более 5 активных;
- **не содержит токен бота** — токен бота в пользовательскую команду не попадает.

## 10. Что сделано и что нет

### Работает и проверено тестами

- Бот: `/start`, текст, голос, фото, вопросы, задачи, тарифы, настройки.
- Разбор одной фразы в несколько записей с предпросмотром и сохранением одной
  кнопкой; повторное нажатие ничего не дублирует.
- Голосовые прямо в чате: скачивание, ограничения, STT, разбор, повтор при
  ошибке; аудио нигде не сохраняется.
- Вопросы по своим записям: модель строит только типизированный план, ответ
  формируется из реальных строк.
- Mini App IMPULSE: все разделы, центральная кнопка микрофона, все состояния.
- Напоминания: постановка по часовому поясу, отмена при выполнении, без дублей.
- Платежи: счёт, pre-checkout, выдача доступа, идемпотентность, отмена,
  возврат, истечение, восстановление на FREE без потери данных.
- Быстрый ввод по отзываемому токену с ограниченными правами.

### Не готово — честно

1. **Ни один внешний вызов не проверен вживую.** Ключей провайдеров и бота нет,
   документация заблокирована шлюзом. Формы запросов к Yandex и Telegram
   написаны по публичным описаниям и требуют проверки на реальных ключах.
   Все внутренние контуры покрыты тестами с подставными провайдерами.
2. **Качество распознавания на живых русских фразах не измерено.** Набор
   эталонных фраз в тестах проверяет схему и разрешение дат, а не модель.
   Замер на реальном провайдере — отдельная работа после подключения ключей.
3. **Цены в Stars не назначены** — по причине из раздела 4.
4. **Распознавание фото не реализовано.** Фото сохраняется с подписью, поле
   `photo_summary` помечено как приблизительное и остаётся пустым. Подсчёт
   калорий по снимку не обещается и не делается.
5. **Правка записи в Mini App** пока ограничена: задачу можно закрыть, вернуть,
   перенести и удалить, но полноценного редактора полей нет.
6. **Перевод SEVER на общие модули `_shared/`** не делался, чтобы не трогать
   работающий продукт.
7. **Связь аккаунта TAVRO с аккаунтом SEVER** заложена в схеме
   (`tavro_accounts.sever_user_id`), но перенос данных между продуктами не
   реализован.
